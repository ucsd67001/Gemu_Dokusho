# GEMuの静かな読書会（GEMu Dokusho）

> 2026-10-10 に組み直した（2回目のリファクタリング）。決めたことと理由は消さず、機能ごとにまとめ直した。
> 各節は「いまの決まり → 理由（日付と配信者の言葉）→ 前の形」の順。日付の流れは最後の「年表」。

## 1. コンセプト（2026-09-27 配信者。同じ日に二度改めた。2026-09-29 に言語化）

### 家にいながら、景色のいい場所で読む。

だれにも邪魔されずに、ひとりで静かに本を読むのが好き。でも、景色のいいところで本をひらくことにも、ちょっと憧れている。
インドア派だから、なかなか行けないけれど。
——そういう人が、自分をブロックのアバターにして、**世界の、読書が気持ちよさそうな場所**の**ベンチに座り、それぞれの本を読む**場所。

話さない。見せ合わない。それでも、**となりのベンチで同じ時間に本をひらいている人がいる**ことだけは伝わる。
読書好きどうしの、ふしぎな一体感。

**ひとことで**：mekuru が「**いっしょに読む**」なら、GEMuの静かな読書会は「**ひとりで読む。でも、ひとりじゃない。しかも、景色のいい場所で。**」

→ 画面の言葉も静かにする。**話させない・競わせない・急かさない。**機能を足すときは、これに合うかで決める。

- サービス名は **「GEMuの静かな読書会」**（2026-09-27 配信者）
- **当面は配信者と仲間1人の2人で使い、使いながら育てる**
- 最初は「神保町のカフェ」だった（同じ日にしまった。`部屋.js` の cafe は `出す: false` で残してある。戻すかもしれない）

**決めごと（これを崩さない）**
- **利用者どうしの直接のやり取りはしない**。話す・送る・フォローするは作らない
- ただ、**読書仲間がいることは感じたい**：いまは「同じ場所に座っている」こと。将来は感想（やり取りにならない形で）
- **カフェだけでなく、綺麗な風景の中で**読む
- **読んでいる本くらいは共有する**（場所の絵のユーザ名と書籍名・X への投稿）
- 数字（冊数・ページ数・時間）は**競わせずに**参考として並べる（「読み方は、人それぞれ」。順位を付けない）

### mekuru（https://www.mekuru.app/ja）との違い（2026-09-29 配信者）

mekuru は「**誰かと一緒に読む部屋**」を作るサービス。
GEMuの静かな読書会は「**ひとりで読む人が、景色と、ほかの読書家の気配を感じる場所**」。

## 3. いまの姿（2026-10-10）

1. **Google でログイン。**はじめての人は、その場でユーザ名と写真（または絵）を決めて登録する（招待制はやめた）
2. **アバターを3枚作る**：①ベンチごと座って本を読む ②ページをめくる ③顔のアイコン（どれも背景は透明）。
   **人の写真でなくてよい。**キャラクターの絵なら、そのキャラクターをブロックにする

## 4. 知らずに触ると壊すこと（CLAUDE.md と同じ）

1. **Firestore の中だけ、名前が ASCII。**ルールの言語が日本語の識別子を受け付けない（Hongaeshi で踏んだ）。
   **翻訳しているのは `public/土台.js` だけ。**画面（`app.js` と `画面/`）は日本語の名前しか知らない。ルールの関数名も英字
2. **試し（/demo）は、土台をまるごと差し替える。**`画面/共通.js` は、URL が `/demo` なら `試し/土台.js`、それ以外は `土台.js` を読む。
   **`土台.js` に関数を足したら、`試し/土台.js` にも同じ名前で足す**（足さないと試しだけが止まる）。
   席と読んだ時間の計算・本棚の読み込みは2つに書かず、**`席の決まり.js`** に置いて両方から読む（2026-10-04。前は同じ中身が2つずつあった）
3. **写真は残さない。**画面で 1024px の JPEG に縮め、functions に渡して OpenAI へ送るだけ。Storage にも Firestore にも置かない。
   残るのは、できあがった絵（`avatars/{uid}/{版}/sit.webp` など）だけ。作り直すと古い版は消す
4. **席の「12時間」は2か所でそろえる**（`firestore.rules` の `stale()` と `席の決まり.js` の `古いとみなす`）。
   3時間以上離れて戻ったら、読んでいた時間を聞く（7-3）
5. **押せるものは `data-する`。**onclick の文字列に値を埋めない（書籍名やユーザ名に `'` が入るとスクリプトが動く。Hongaeshi で実際に穴だった）。
   `data-する="…"` と `data-*` で渡し、`動き`（`画面/共通.js`）で受ける。欄が変わったときは `data-変わる` と `変わったら`／`打ったら`。
   ⚠️ 2026-09-27 に、行の範囲を指定して消したとき「投稿しないで終える」の処理まで消えていた（2日間効かなかった）。
   **押せるものと `動き` の対応は、直したら必ず突き合わせる**

## 7. 機能ごとの決まり

### 7-1 アバター（`functions/index.js` の makeAvatar）
- ①は**写真から**、②③は**①から**作る。写真から何回も作ると別人になる（顔も服も毎回変わる）
- ⚠️ **上げるのは人の写真とは限らない**（2026-09-27、二人ともキャラクターの絵だった）。
  「写真の人」を前提にした指示だと、**キャラクターが人間に描き替えられた。**→ 写っているものをそのままブロックにする。
  **猫耳・しっぽなどは名指しで残させる**（落ちやすい。配信者の一枚目は耳が目立たず、しっぽが消えた）
- **ベンチごと描かせる。**背景のベンチに重ねると、向きと高さが合わずに浮く。座るものは**小さな木のベンチ**
  （2026-09-27、カフェの椅子から替えた。空のベンチの絵と言い方をそろえる）
- アバターは**正面ではなく45度斜め**（右前）を向かせる（2026-09-27 配信者）
- 「右前を向く」で頼んでも、**左を向いて描かれることがある**（2026-09-27、配信者の一枚目）。
  → 描いたあとに gpt-4.1-mini で左右どちらを向いているかを見て `avatar.facing` に残す（`detectFacing` は、それより前に作ったアバター用）。
  場所の絵では、**席の `向き` と絵の向きが違えば左右を反転**する。見分けを間違えたら、自分のページの「向きを反対にする」（`users.flip`）
- ⚠️ **背中（後ろから見たアバター）は作らない**（2026-10-10 配信者）。背中を使うのは「手前の席」（背中がこちらを向く席。`部屋.js` の `姿: "背中"`）だけで、
  いまの場所には無い（あったのはカフェだけ）。使われない絵に料金の約4分の1を払っていた。
  手前の席のある場所を足すときは、functions の `addBack`（残してある）と、自分のページの「背中のアバターを足す」（外した）をつなぎ直す。
  背中の絵が無い人は、手前の席でも顔の絵のまま座る（`画面/ベンチ.js` の `描くもの`）

### 7-3 席を保つ時間と、画面を消して読む人（2026-10-04 配信者）
- 座っているあいだ、画面が1分ごとに「生きている」を送り、席の `seen` を延ばす。**12時間延びていない席は空き**とみなす
  （タブを閉じると「立つ」が届かないことがあるため。空いた席にはだれでも座れる）
- 使い方は「場所に入る → スマホの画面を消して本を読む → 読み終えたら画面をつけて、読み終える」。
  前は3分で席を空き扱いにしていたので、30分〜数時間後に画面をつけると、席を立った扱いになっていた
- **席は12時間保つ**（ひと晩の消し忘れまで）
- **3時間より短く**離れて戻ったら、そのまま読んでいたものとする（聞かない）
- **3時間以上**離れて戻ったら「おかえりなさい ― 画面を消してから○時間○分たちました。そのあいだ、読み続けていましたか？」と聞き、
  読んでいた時間を **時間：分** で入れてもらう（配信者「ずっと読み続けていないと思うので、手入力で自己申告」。最初は「30分以上」で聞くとしたが「3時間以上」に改めた）。
  「読んでいませんでした」なら0分。**申告した時間より後ろ（戻るまで）は休みとして記録から引く**（`席の決まり.js` の `離席を書き込む`・`記録にする`）。
  記録は、休みで分かれた区間ごとに1件。場所の絵の下の欄と「読み終える」の時間も、休みを引いた時間
- 「おかえりなさい」の画面は、✕・外側・Esc では閉じない（答えてもらう画面）
- **12時間を過ぎて**戻ったら、記録せずに席を立つ（「この回は記録に残りません」）
- 答えるまでは「生きている」を送らない（送ると、離れていた時間が分からなくなる）
- 3時間は `席の決まり.js` の `聞く離れ`、12時間は `古いとみなす` と `firestore.rules` の `stale()`。
  ⚠️ 12時間のあいだ、消し忘れた人の席は埋まったまま（ほかの人からも座っているように見える）

### 7-6 本・申請・本棚（2026-09-29 配信者）

無ければ利用者が申請して**仮登録**（`books` の `status: pending`）。**申請した本人は、仮登録のままその本で座れる。**
**管理者が承認すると本登録**（`approved`）になり、みんなが選べる。見送り（`rejected`）は、本人の一覧からも消える。
- 前は書籍名を自由に打ち込んでいた。表記ゆれで同じ本が別の本になるのを防ぐため、選ぶ形にした（Hongaeshi の申請を参考に）

    HEAD は 404 になるので GET で、飛び先（Location）だけを見る。
    ⚠️ `link.amazon/…` は途中で `amzlinks.in`（Amazon の中継先）を通る（link.amazon → amzlinks.in → amazon.co.jp）。

  - 「**＋ 本の登録を申請する**」はボタンにして目立たせる（2026-09-30。見落とされた。⚠️ さがす欄に URL を貼る形は作ったが、配信者の希望で外した）

  - **二重の申請を減らす**：確かめた ISBN の本が本棚にあれば、申請の前に「もう本棚にあります」と出し、その本を選べる
  - **管理画面で、承認の前に書誌を確かめる**：「ISBN から書誌を引き直す」で、書籍名・著者・出版社を openBD の表記に入れ替えられる。ページ数も直せる

  読了の印は付けられない。X の文と絵にも書籍名を入れない。ベンチでひらかれた本には数えない
- ⚠️ **選んだ本の取り違えを防ぐ**（2026-10-01 配信者「『推し、燃ゆ』を選んだのに『「知」のソフトウェア』が出た」）：

**Hongaeshi の本棚を写す**（2026-09-29 配信者「Hongaeshi の図書データをコピーして」）：

- ⚠️ サイトの下に「GEMuの静かな読書会は Amazon アソシエイト・プログラムの参加者です。適格販売により収入を得ています。」を出す
  （規約で要る。`index.html` と `demo.html`）。⚠️ **アソシエイトの管理画面に gemu-dokusho.web.app を足すのは配信者の作業**

- **読書の記録ページは1週間で消す**（2026-10-10 配信者「例えば、1週間たったら消す、みたいにしたい」）。functions の `cleanShares` が毎日4時（日本）に、
  作ってから1週間たった `shares` と Storage の絵を消す。消したあとにリンクを開くとトップへ移る。「読み終える」の画面の注にも書いてある
- **スマホ**：準備ができたら、小さな画面で次の3つから選んでもらう（2026-10-04 配信者）：
  **X のアプリで投稿する**（`twitter://post?message=…`。アプリの投稿画面を直接開く）／
  **共有から投稿する**（共有シートで X を選ぶ。共有シートが使えるブラウザだけ）／**ブラウザの X で投稿する**（アプリが無い人用）
  - 前は「X で投稿する」の1つで、x.com の投稿画面のリンクを開いた。スマホは**人が自分でリンクを押したときだけ**アプリで開くので、
    それより前の「絵を置き終わってから、ページの側で移る（`location.href`）」ではウェブ版の X が開いていた
  - ⚠️⚠️ 2026-10-04 配信者の iPhone：x.com のリンクで X のアプリは起動したが、**アプリは投稿画面を開かず、アプリの中のブラウザで x.com を開いた**
    （ログインが別扱いでログイン画面が出て、Google のログインも止められていた）。それで3つにした
  - ⚠️ 絵を置き終わってから新しい窓を開くと止められ、X が立ち上がらなかった（2026-09-27）。リンクは同じタブで開く
  - アプリの呼び出しは、アプリが無いと何も起きないので、戻ってくるまで小さな画面を閉じない。この画面は ✕・外側・Esc では閉じない
  - 読んだ時間の記録は、この画面を出す前に残す
- **パソコン**：押した瞬間に新しい窓を開いておき、絵を置き終わったら X へ移す（絵を置き終わってから開くと、ポップアップとして止められる）
- **X に載る絵**は画面の canvas で描く（日本語の字を画面のフォントで書けるため）。アバターは Storage にあり、そのまま描くと
  canvas が書き出せなくなるので、`borrowImages` で data URL にして借りる
- 絵には、そのとき座っている**ほかの人のアバターも写る**（2026-09-30 配信者「一緒に写ったまま投稿してOK」）。
  **全員にユーザ名と書籍名を付ける**（2026-09-30 配信者「他のユーザのユーザ名と書籍名も表示してOK」）。自分だけ紫の縁。
  同じベンチの2人目は1段下げる。幅は絵の 12% に詰め、長いものは … で切る（8人でも重ならない）

### 7-9 画面の言葉と見た目（2026-10-04 のリファクタリングで決めた）
- **言葉は用語集の左の列だけ**（2 章）
- **時間は「2時間5分」の形**（60分未満は「45分」）。読み終える画面・X の投稿文・X に載る絵・読書の記録ページも同じ（配信者が選んだ）。
  画面は `画面/共通.js` の `時間に`／`分に`、読書の記録ページは functions の写し
- 「だれ」はひらがな。注（小さな字の文）は句点で終える
- 待っているあいだの積み木は「…」を付けない。押したボタンの字と、欄の下の途中経過は「…」を付ける
- うまくいかなかったときの字は赤い字（`誤りの字`）。お知らせの文は「ユーザ名を直せませんでした」のように**何が**できなかったかを書く。英語の誤りは出さない
- **主なボタンは黒、控えは枠だけ**（配信者が黒を選んだ）。紫はリンクと小さな差し色だけ
- 小さな画面のボタンは縦に並べる（主なボタンが上）。答えてもらう画面（おかえりなさい・スマホの X 投稿）は閉じられない。ほかは Esc で閉じる
- ページの大見出しの上の小さな英字（Places など）は飾りとして残す（配信者が選んだ）。数字の見出しは日本語（今日・この7日間・これまで・冊数・ページ数）
- ボタンの上の余白は3段（`上の狭い間`・`上の間`・`上の広い間`）。値で変わるもの（位置・縦横比）のほかは `style=""` を書かない

### 7-10 権限と管理者（2026-09-30 配信者と確かめた）
Hongaeshi は3段（管理者／受取人／利用者）だが、こちらは**お金が動かないので受取人が要らない**。
- **管理者**（配信者だけ）：`admins/{uid}` に文書がある人。メニューに「管理」が出て、本の申請を直す・書誌を引き直す・本登録にする・見送る
- **利用者**：Google でログインした人。本を申請できる（承認までは仮登録で、自分だけが使える）
- ⚠️ **守りはデータの決まり（firestore.rules の `isAdmin()`）にある。**画面で「管理」を出しても、管理者でなければ承認できない
- ⚠️ **こちらから利用者のアバターを作り直す入口を作らない**（2026-09-27。「今回だけ」と頼まれて合言葉つきの入口を足そうとしたら、守りを弱める変更として止められた）
- 管理画面に足せそうなもの（必要になったら）：本登録の本の直し・外し／利用者の一覧／アバター作りの回数

## 8. 動かす・デプロイ・鍵・道具

### 動かす
```bash
firebase serve --only hosting --project gemu-dokusho --port 5050
```
- 試し：`http://localhost:5050/demo`（タブを2つ開いて、2人で同じ場所に入るところまで見る。スマホの幅 375px も見る）
- 本体：`http://localhost:5050/`（本物の Firebase につながる）
- ⚠️ 手元のサーバーはキャッシュを止めないので、直したファイルが古いまま読まれることがある（本番はキャッシュさせない設定）

### デプロイ
```bash
firebase deploy --project gemu-dokusho --only hosting
firebase deploy --project gemu-dokusho --only firestore:rules,firestore:indexes,storage
FUNCTIONS_DISCOVERY_TIMEOUT=60 firebase deploy --project gemu-dokusho --only functions
```
⚠️ **Functions と hosting を一緒に出さない**（Hongaeshi で、Functions の後片づけのエラーで hosting が公開されないまま終わった）。
古いイメージを1日で消す設定は 2026-09-27 に入れた（`firebase functions:artifacts:setpolicy`）。
functions の読み込みが10秒で時間切れになることがあるので、`FUNCTIONS_DISCOVERY_TIMEOUT=60` を付ける。

### 鍵
- **OpenAI の鍵は Secret Manager の `OPENAI_API_KEY`。****Hongaeshi と同じ鍵**（2026-09-27 配信者の指示。hongaeshi の Secret Manager から、画面に出さずに写した）
  - 鍵を替えるとき：`firebase functions:secrets:set OPENAI_API_KEY --project gemu-dokusho`（配信者が打つ）→ functions を上げ直す
  - ⚠️ **GEMu_AITuber の `.env` の鍵は使わない**
- 場所の絵を作る道具も、同じ Secret Manager から firebase コマンドで読む。**鍵をファイルに書き出さない**
- `functions/.env` には `IMAGE_MODEL=gpt-image-1` だけを置く（鍵ではない。**これが無いと、非対話のデプロイが止まる**）
- 管理用の鍵（サービスアカウント）は **`~/.gemu-dokusho/鍵.json`**（リポジトリの外。配信者が Firebase コンソールの
  「プロジェクトの設定 → サービス アカウント → 新しい秘密鍵を生成」で作って置いた）。**中身を画面に出さない**

### 管理者を決める（**リポジトリにメールや uid を書かない**）
```bash
node 04_tools/管理者にする.mjs                 # いまの管理者を並べる
node 04_tools/管理者にする.mjs <uid> [名前]     # 管理者にする
node 04_tools/管理者にする.mjs --外す <uid>     # 管理者をやめさせる
```
- ⚠️ `admins` は**ルールで書き込み禁止**。増やせるのは Admin SDK（この道具）からだけ（画面から増やせる入口を作らない）
- uid は `firebase auth:export` か、コンソールの Authentication で分かる。管理者になった人がアプリを開き直すと、メニューに「管理」が出る

### 場所を足す

   （画風は「斜め上から見た、やわらかい立体のミニチュア」にそろえる。人・動物・ベンチは描かせず、手前に何も無い広場をあけさせる）

4. `firestore.rules` の `okRoom` に id を足す（足さないと座れない）→ ルールと hosting を上げる
5. 広場が狭ければ、構図はそのままに広げられる：`node 04_tools/部屋を作る.mjs {id} 2 --広げる`（道具の `広げ方` に広場の言い方を書く）
