# GEMuの静かな読書会（GEMu Dokusho）

## コンセプト（2026-09-27 配信者。同じ日に二度改めた）

**家にこもって、誰にも邪魔されずに、一人で静かに本を読むのが好き。でも、景色のいいところでの読書にも憧れる。
インドア派だから、なかなか行けないけれど。**——そういう人が、**家にいながら、世界の景色のいい場所のベンチで読む。**
話さない。見せ合わない。それでも、となりのベンチで同じ時間に本をひらいている人がいる、ということだけが伝わる。
→ 画面の言葉も静かにする。**数を誇らない、急かさない、競わせない**（記録は自分のためだけ。順位は作らない）。

- 場所は「世界の、読書が気持ちよさそうな観光地」を増やしていく。**最初はローテンブルク（プレーンライン）**
- 最初は「神保町のカフェ」だった（同じ日にしまった。`部屋.js` の cafe は `出す: false` で残してある。戻すかもしれない）
- サービス名は **「GEMuの静かな読書会」**（2026-09-27 配信者）

### mekuru との違い（2026-09-29 配信者）
- **利用者どうしの直接のやり取りはしない**（わずらわしいので）。話す・送る・フォローするは作らない
- ただ、**読書仲間がいることは感じたい**：いまは「同じ場所に座っている」こと。将来は**感想**（やり取りにならない形で）
- **カフェだけでなく、綺麗な風景の中で**読む
- **読んでいる本くらいは共有する**（名札の書名・X への投稿）
- **読み方は、人それぞれ**（2026-09-29 配信者）：競わせないが、参考として「たくさんの本を（読了した冊数）」
  「たくさんのページを（読了した本の総ページ数）」「長い時間を」の3列に、**これまで全部**の上位3人を名前と数で出す。
  **順位の数字は付けない。**志向が違う人がいる、と伝えるため。場所の一覧の下。数えるのは functions の `readerStats`
  （記録は本人しか読めないまま、上位3人の名前・顔・数だけを返す）。冊数とページ数は、「読み終える」で
  「この本を最後まで読んだ」に印を付けた本だけ（`finishes`）

自分の写真（またはキャラクターの絵）から**ブロック風（マインクラフトのような）アバター**を作り、
場所の**ベンチ**に座って、それぞれの本を読む。
mekuru（https://www.mekuru.app/ja）に近いが、**当面は配信者と仲間1人の2人で使い、使いながら育てる。**

## いまできること（2026-09-27 に作った最初の形）

1. **Google で入る。**はじめて入った人は、その場で名前と写真を決めて登録する（Hongaeshi と同じ。招待制はやめた）
2. **初回：名前と写真（または絵）を決める → アバターを4枚作る**
   ①椅子ごと座って本を読む姿 ②ページをめくる姿 ③顔のアイコン ④後ろから見た姿（どれも背景は透明）
   **人の写真でなくてよい。**キャラクターの絵なら、そのキャラクターをブロックにする
3. **廊下**：部屋の一覧（いまは「カフェ」だけ）。誰が中にいるか顔で見える
4. **カフェ**：読む本の題を入れて席に着く（4席）。部屋の絵に、自分と仲間のアバター・名前・書名が出る。
   ときどきページをめくる（①と②が入れかわる）
5. **読み終える → X に投稿しますか？**：はいなら、その場の絵（場所・座っている人・空のベンチ）に書名と読んだ時間を載せた
   1200×630 の絵を作り、**読書の記録ページ（`/s/{id}`）**のリンク付きで X の投稿画面を開く（押すのは本人）
6. **記録**：席に着いていた時間（今日・7日・これまで、1回ごと）
7. **自分**：名前を直す・アバターを作り直す（1人1日5回まで）・ログアウト
8. **試し（/demo）**：Firebase を使わずに、ブラウザの中だけで全部動く。タブを2つ開くと2人になる

## 作りの要点（ここだけは先に読んでほしい）

### Firestore の中だけ、名前が ASCII
ルールの言語が日本語の識別子を受け付けない（Hongaeshi で踏んだ）。
**翻訳しているのは `public/土台.js` だけ。**画面（`app.js`）は日本語の名前しか知らない。

| コレクション | 中身 | 書くのは |
|---|---|---|
| `meta/usage` | アバターを作った回数（全員ぶん・今日） | **functions だけ** |
| `users/{uid}` | `name`, `created`, `avatar{status, step, sit, turn, face, error, at, day, count}` | `name` は本人、`avatar` は **functions だけ** |
| `rooms/{room}/seats/{番}` | `uid`, `title`, `since`, `seen` | 本人 |
| `logs/{id}` | `uid`, `room`, `title`, `from`, `to` | 本人 |

### 試し（/demo）は、土台をまるごと差し替える
`app.js` は、URL が `/demo` なら `試し/土台.js`、それ以外は `土台.js` を読む。
⚠️ **`土台.js` に関数を足したら、`試し/土台.js` にも同じ名前で足す。**足さないと試しだけが止まる。

### 写真は残さない
写真は画面で 1024px の JPEG に縮め、**functions に渡して OpenAI へ送るだけ。**Storage にも Firestore にも置かない。
残るのは、できあがった絵（`avatars/{uid}/{版}/sit.webp` など）だけ。作り直すと古い版は消す。

### アバターの作り方（`functions/index.js`）
- ①は**写真から**、②③④は**①から**作る。写真から何回も作ると別人になる
- ⚠️ **上げるのは人の写真とは限らない**（2026-09-27、二人ともキャラクターの絵だった）。
  「写真の人」を前提にした指示だと、**キャラクターが人間に描き替えられた。**→ 写っているものをそのままブロックにする。
  **猫耳・しっぽなどは名指しで残させる**（落ちやすい）
- **席は4つ（テーブルの左右×奥と手前）。**テーブルに向くと、奥の席は顔が、手前の席は背中がこちらを向く。
  左右は反転で作れるので、要るのは①（顔）と④（背中）の2つ。`部屋.js` の席の `姿` が "顔"／"背中"
- ④が無いアバター（④を足す前に作ったもの）は、手前の席でも①のまま座る。「自分」の「背中の姿を足す」で④だけ作れる（`addBack`。1回に数える）
- **椅子ごと描かせる。**背景の椅子に重ねると、向きと高さが合わずに浮く
- 人は「右前を向く」で頼むが、**左を向いて描かれることがある**（2026-09-27、配信者の一枚目）。
  → 描いたあとに gpt-4.1-mini で左右どちらを向いているかを見て `avatar.facing` に残す（`detectFacing` は、それより前に作ったアバター用）。
  部屋では、**席の `向き`（テーブルの方）と絵の向きが違えば左右を反転**する。見分けを間違えたら「自分」の「向きを反対にする」（`users.flip`）
- ローテンブルクは**二人掛けのベンチ4つ、8人まで**（2026-09-27 配信者）。**一人掛け（アバターはベンチごと）を2つ並べて**二人掛けに見せる。
  座る順は、まず4つのベンチの片側に1人ずつ、埋まったら隣に（一人で静かに読みたい人向け）。同じベンチに2人いれば名札を左右に振る
- アバターは**正面ではなく45度斜め**を向かせる（2026-09-27 配信者）
- **満席のとき**（2026-09-27 配信者「9人目に、いまは入れないことをうまく伝えたい」）：
  場所の一覧で札が「満席」になる／入っても題を聞かず、手もとに「ベンチが空くのを待っています」を出す／
  空いたらその場で「ベンチがひとつ空きました」（別のタブを見ていれば、タブの題名も変える）／
  題を入れているあいだに最後の1席が埋まったら「ちょうど今、最後のベンチが埋まりました」。
  ⚠️ 題を聞く窓は、**席の様子が届いてから**出す（前は開いた瞬間に出していて、9人目にも題を聞いていた）
- **1人1日5回、全員あわせて1日30回まで**（日本の日付。`functions/index.js` の `一日の上限` と `全員の一日の上限`）。
  だれでも登録できるので、全員ぶんの上限が料金の歯止め。1回で3枚描くので、料金はその3倍

### 席は「生きている」を1分ごとに送る
タブを閉じると「立つ」が届かないことがある。**`seen` が3分延びていない席は空き**とみなす
（`firestore.rules` の `stale()` と、`土台.js` の `古いとみなす` をそろえる）。

### 読んだ時間は「読み終える」で終えたときだけ記録する（2026-09-29 配信者）
座っているあいだは書かない。本を替えた区切りは `土台.js` の `いま.区切り` で覚えておき、
「読み終える」（投稿しないで終える／X に投稿して終える）で `立つ({ 記録する:true })` したときに、区切りごとに1件ずつ書く。
ほかの頁へ移る・タブを閉じる・ログアウトは、席を立つだけで記録しない。記録を読めるのは本人だけ。
⚠️ 2026-09-27〜29 の記録には、この決まりの前の「閉じただけの回」が混ざっている（消していない）。
⚠️ 2026-09-27 に、行の範囲を指定して消したとき「投稿しないで終える」の処理まで消えていた（2日間効かなかった）。
   **押せるもの（`data-する`）と `動き` の対応は、直したら必ず突き合わせる**

### 名札は、人の絵と別の層
人の中に名札を入れると、手前の人が奥の人の名札を隠す。舞台の最後に名札だけを重ねている。

### 押せるものは data-する
onclick の文字列に値を埋めない（題や名前に `'` が入るとスクリプトが動く。Hongaeshi で実際に穴だった）。
`data-する="…"` と `data-*` で渡し、`app.js` の `動き` で受ける。

## 本と、本の申請（2026-09-29 配信者）

入室（と本を替える）のときに、**題を名札に出すか出さないか**を選び、出すなら**登録済みの本から選ぶ**。
無ければ利用者が申請して**仮登録**（`books` の `status: pending`）。**申請した本人は、仮登録のままその題で座れる。**
**管理者が承認すると本登録**（`approved`）になり、みんなが選べる。見送り（`rejected`）は、本人の一覧からも消える。
- 前は題を自由に打ち込んでいた。表記ゆれで同じ本が別の本になるのを防ぐため、選ぶ形にした（Hongaeshi の申請を参考に）
- 申請は書名・著者名・出版社名が必須、ISBN とひとことは任意
- 題を出さなかった人：名札は名前だけ。記録には「（題を出さずに読んだ本）」。読了の印は付けられない。X の文と絵にも題を入れない

### Hongaeshi の本棚を写す（2026-09-29 配信者）
`node 04_tools/Hongaeshiから写す.mjs` → `public/本棚.json`（書誌だけ。93冊）→ hosting を上げる。
画面は、これを**本登録の本**として一覧に混ぜる（id は `h-…`）。Firestore には入れていない（こちらの管理用の鍵が無いため）。
- Hongaeshi の books は**だれでも読める**ので、鍵を使わずに公開の入口（REST）から読む
- 紹介文（AI の文）と Amazon のリンク（Hongaeshi のアフィリエイトのタグ付き）は写さない
- ページ数がある本は、読了の印を付けたときに総ページ数がはじめから入る
- Hongaeshi に本が増えたら、もう一度流して上げ直す

### 管理者を決める（Firebase コンソールで。**リポジトリにメールや uid を書かない**）
1. Authentication の「ユーザー」で、管理者にしたい人の **UID** を写す
2. Firestore で `admins` というコレクションを作り、**文書 ID をその UID** にする（フィールドは何でもよい。例：`ok` = true）
3. その人がアプリを開き直すと、メニューに「**管理**」が出る。仮登録の本を、書名などを直してから「本登録にする」か「見送る」

## 部屋の絵を差し替える

1. `node 04_tools/部屋を作る.mjs` で `04_tools/下書き/` に何枚か作る
2. 気に入った1枚を `public/部屋/cafe.webp` に置く
3. `public/部屋.js` の `絵:` にその道を書き、**席の座標を絵を見て測り直す**（仮の絵と椅子の場所が違う）

## 決めたこと・保留していること

- **X は投稿画面を開くだけ**（2026-09-27 決定）。X の API は有料で開発者登録が要る。
  - ⚠️ **投稿画面（intent）には画像を添付できない。**→ 絵を置いた記録ページ（functions の `sharePage`）のリンクを付け、
    **X がリンクから絵（og:image）を読み取って大きく出す。配信者はこの形でよい**（2026-09-27、実際の投稿を見て）
    - ⚠️ 一度「画像を添付したい」と取り違え、コピーして貼り付け／画像を保存の手順を作った。**要らない**（配信者）。外した
    - **スマホは、このページのまま X へ移る**（`location.href`）。絵を置き終わってから新しい窓を開くと止められ、X が立ち上がらなかった
    - パソコンは、押した瞬間に新しい窓を開いておき、絵を置き終わったら X へ移す
  - 絵は画面の canvas で描く（日本語の字を画面のフォントで書けるため）。アバターは Storage にあり、そのまま描くと
    canvas が書き出せなくなるので、`borrowImages` で data URL にして借りる
  - 絵にも記録にも**名前は入れない**（ほかの人も写るため）。`shares/{id}` と Storage の `shares/` はだれでも読める
  - 投稿の窓は**押した瞬間に開く**（絵を置き終わってから開くと、ポップアップとして止められる）
- **招待制はやめ、ログインしたらその場で登録**（2026-09-27 配信者の決定。Hongaeshi と同じ）。料金の歯止めは回数の上限
- **部屋の絵は「添付の部屋のような、やわらかい立体の絵」、人はブロック風**（2026-09-27 配信者の選択）。
  カフェは**中世ヨーロッパで、明るい雰囲気**
- 環境音・読書仲間・部屋を増やす・独自ドメインは、使いながら決める
